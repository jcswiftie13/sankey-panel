輸入契約

必要：investigation（switchId、iface、direction、deltaBps）、hops（非空，每筆有 switchId）。

畫法說明

      
1. 為什麼下游會比較大

      
一跳可能有多條 uplink。你追進來的那條 in 只是這台 switch 進來的流量之一。下游看到的 out 增加可以大於它（A→B 10G，B→C 20G）。多出來的量不是這台 switch 生出來的，是其他輸入——別的上聯、別的來源。

      
2. 追查方向

      
封包方向永遠左到右，不做兩套座標，不左右鏡射。差別只在追查起點釘在哪一側。

      

        
模式你看的 counter下一跳起點位置JSON

        
          
追終點某條 in 增加貢獻大的 out最左kind:"destination" 或 direction:"in"

          
追來源某條 out 增加貢獻大的 in最右kind:"source" 或 direction:"out"

        
      

      
追終點 hop 填 outputs；追來源 hop 填 inputs。同一台 switch 出現多次（雙 uplink 匯入核心）會合併成一個盒子，不畫成兩台。

      
2b. 同層互連（tier）

      
欄位預設照最長路徑排。同一層彼此互連時（bdr↔dci 跨 DC），互連下游的機器會被推到右邊一欄，同一層被拆成兩欄。把同層的 hop 都標同一個 tier（字串內容自訂，程式只比對相同與否）：

      
    
        
  • 同 tier 的機器鎖在同一欄；欄位順序照舊由拓樸自動推（整群視為一個節點跑最長路徑，tier 內部的邊不參與排欄）。沒標的 hop 完全照舊。
    • 
        
  • tier 內部的邊畫成欄右側的弧帶：往右凸再折回，厚度與青帶共用同一把比例尺。守恆、可歸因量都照常經過這些邊。
    • 
        
  • tier 標到讓群組之間繞成環（甲群 → 乙 → 甲群）時會警告並忽略 tier 退回最長路徑；tier 內部有環（a→b→a）時環上的量無法完整歸因，也會警告。
    • 
      

      
每層只跟前 N 名或佔比 ≥ 門檻（預設前 3 名 / ≥ 10%）時：

      
    
        
  • 其他輸出：這層 focus 增加量裡沒跟下去的 port（截斷、太小、已滿 N 名）。
    • 
        
  • 其他輸入：跟下去的出口／入口總量比剛追進來那條更大（別的上聯、沒追的來源）。
    • 
      

      
已知 in ＋ 其他輸入 ＝ 已追查 out ＋ 其他輸出

      
JSON 可顯式給 otherInBps / otherOutBps；沒給就由平衡式補缺口。同一層兩種可以同時有。

      
4. 視覺定案

      
    
        
  • 青色長帶：有跟下去的 uplink／追查路徑，帶寬用實際 increment。
    • 
        
  • 殘差不進走廊：不畫成穿越別台的長色帶，也不做盒子內底部 chips。
    • 
        
  • 殘差貼在該台外側的虛線色塊：其他輸入在左、其他輸出在右。高度跟 Gbps 等比，與青帶共用同一把比例尺；標籤與數量寫在色塊旁。有追查與沒追查的比例才看得出來。
    • 
        
  • 殘差是盒子左右 port 疊裡的真槽位，跟已追查 port 一起排版。同一台左右兩側的色塊厚度總和相等；但每列有最小高度與間距，兩疊的總高度不會剛好一樣——守恆看色塊厚度，不是看疊起來的總高度。
    • 
        
  • 小於該台自己讀數誤差（已知 in 與已追查 out 取大者的 0.5% ＋ 1 bps）的殘差不畫，免得浮點雜訊長出一塊。圖、hop 摘要、Mermaid 同一個門檻。
    • 
        
  • 盒子裡只畫已追查 port。殘差不用斜線填滿整台 switch，免得看起來像另一台機器。
    • 
        
  • 追查終止葉節點：灰色虛線小卡，寫「追查終止」「未再往下追」加 iface 與帶寬。不是又一台 switch。
    • 
        
  • k8s：同一條 Sankey 接下去，switch → node（虛線盒）→ pod（葉，標 namespace/name）。node 用同一套截斷，沒跟的 pod 併成該 node 的其他輸出。不一開始把上百個 pod 畫成細帶。
    • 
        
  • hop 數字摘要放圖下方，是圖外資訊，不是盒子內標籤。
    • 
      

      
5. 平衡 Sankey 怎麼讀

      
只有這一種讀圖方式。圖上的帶寬一律是實際 increment，缺口用其他輸入／其他輸出補齊，所以每一台都守恆：

      
已知 in ＋ 其他輸入 ＝ 已追查 out ＋ 其他輸出

      
「能歸因到追查起點多少」是圖外資訊：看圖下方 hop 摘要的「可歸因」欄，或把游標移到帶子上看 tooltip。不另外做一種只畫貢獻的圖，免得同一張拓樸有兩套數字。

      
6. 明確不做

      
    
        
  • 不自動偵測網路上的 switch／counter。
    • 
        
  • 不做帳號、資料庫、後端儲存追查紀錄。
    • 
        
  • 不把追來源畫成整張圖左右鏡射。
    • 
        
  • 不把殘差畫成一條穿越所有 hop 的全域 sink 河。
    • 
        
  • 不把「沒再往下追的對端」畫成完整 switch 盒子。
    • 
      

      
7. CLI

      
tools/trace_sankey.py：先算 residual 再畫／印。純文字離線可用，本機有 plotly 就能出互動 HTML。

      
make draw FILE=trace.json
python3 tools/trace_sankey.py samples/classic.json
python3 tools/trace_sankey.py trace.json --mermaid sankey
python3 tools/trace_sankey.py trace.json --plotly out.html
